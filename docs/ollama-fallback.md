# 可选兜底：本地 Ollama 翻译模块（设计稿，未实现）

> 状态：**设计阶段**。以下内容仅为设计，不包含任何已实现代码。
> 在接口确认前，本项目不会修改 Devin 安装目录、不会劫持网络通信、
> 不会注入 DOM/API。该模块可独立开关，关闭后对原有规则零影响。

## 目标

当规则生效不完整、可见思考说明仍出现英文自然语言时，提供一个
**用户主动触发**的本地翻译通道：把用户复制出来的可见文本发给
本机 Ollama，得到中文对照译文。

## 非目标

- 不读取 Devin 的隐藏推理 / 内部思考链
- 不自动抓取 Devin 界面内容（不依赖 DOM、CDP、UI Automation）
- 不修改 Devin 安装目录或其进程
- 不在网络层做拦截/改写
- 不把翻译结果回写进 Devin 会话

## 设计

```
用户复制可见文本 → 保存为 .txt → scripts/translate_ollama.py <file>
                                      │
                                      ▼
                            本机 Ollama (http://localhost:11434)
                            默认模型: qwen2.5:7b / 可配置
                                      │
                                      ▼
                  输出 <file>.zh.md：英文原文 + 中文译文对照
                  代码块/路径/日志/URL 原样保留，不翻译
```

### 保护措施

1. **只处理用户显式提供的文件**，与 `check_drift.py` 同一边界。
2. 翻译 prompt 中明确要求：代码、命令、路径、URL、API、日志原文
   保持不变；只翻译自然语言句子。
3. 默认 `ollama` 必须是本机 `127.0.0.1:11434`，不接受远程 endpoint，
   防止文本被发往第三方。
4. 失败时原样输出原文并提示，不产生半成品误导。
5. 独立开关：`--enable-ollama` 才启用；不配置则模块不存在。

### 与规则的关系

- 规则（always_on）是第一道防线：让模型直接用中文生成。
- Ollama 兜底是第二道：只对**已经产生**的英文可见文本做事后翻译，
  不声称能改变模型内部状态。
- 两者可独立使用；卸载规则不影响翻译脚本，反之亦然。
