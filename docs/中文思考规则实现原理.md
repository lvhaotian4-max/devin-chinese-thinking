# 中文思考规则实现原理

> 本文解释"用户规则 → 文件安装 → Devin 加载 → 可见中文输出"的完整链路，
> 并如实区分**已验证**与**未验证**环节。

## 一、总链路

```
用户规则模板 (templates/*.md)
        │  install.ps1 写入 + 自动备份 + 幂等标记
        ▼
规则文件落盘
  ├─ ~/.devin/rules/chinese-thinking.md      (用户级, always_on)
  ├─ %APPDATA%/devin/AGENTS.md               (标记块追加)
  ├─ ~/.codeium/windsurf/memories/global_rules.md (旧版兼容)
  └─ [可选] %APPDATA%/devin/config.json hooks + hooks/*.mjs
        │  Devin 会话启动时读取（规则文件）；每次提问时触发（hook）
        ▼
注入 Agent 上下文的 always-on 指令
        │  模型据此调整"可见文本"的生成语言倾向
        ▼
Agent 可见输出：思考说明 / 计划 / 工具调用说明 / 回复 / 总结 → 简体中文
```

## 二、逐环节说明

### 1. 用户规则 → 文件安装与验证

`install.ps1` 做的事：

- 探测候选路径（`~/.devin/rules/`、`%APPDATA%\devin\AGENTS.md`、
  codeium memories 等）；
- 写入前把已有文件备份为 `.bak-<时间戳>`；
- 用 `<!-- devin-chinese-thinking:v2 -->` 标记块管理追加内容，
  重复安装幂等，冲突文件不覆盖；
- 全部写入 UTF-8 无 BOM，保证中文不乱码；
- `-IncludeHooks` 时额外安装 hook 脚本并合并 `config.json`
  （同样先备份，且检测到已有 chinese-thinking hook 就跳过，
  避免重复注入）。

`status.ps1` 只读复查：文件是否存在、是否含标记、编码、frontmatter、
hook 注册状态、node 可用性、Devin Desktop 是否安装。

### 2. Devin 规则加载（文档确认；Desktop 部分实测）

依据 Devin Desktop 内置官方文档
`resources/app/extensions/windsurf/devin/share/devin/docs/extensibility/rules.mdx`：

- `AGENTS.md`（项目根 / `%APPDATA%\devin\AGENTS.md` 全局）→ always-on；
- `.devin/rules/*.md`（项目级与 `~/.devin/rules/`）→ 支持
  `trigger: always_on` frontmatter；
- `.windsurf/`、`.cursor/`、`.claude/` 等外部格式 → 兼容读取；
- codeium memories 路径不在该文档中，但**本机实测被加载**
  （本会话系统提示中出现了该文件内容）。

加载时机：**会话启动时**。已打开的会话不会热更新，必须新开会话或重启。

### 3. Hook 注入（每次提问）

`config.json` 中注册的命令型 hook 在 `SessionStart` 与
`UserPromptSubmit` 事件触发，脚本向 stdout 输出
`hookSpecificOutput.additionalContext`，内容为语言指令。
官方文档：`extensibility/hooks/lifecycle-hooks.mdx`。

**这是本机中文输出最稳定的来源**：每个用户 prompt 都重新注入指令，
长上下文中不易被稀释。本会话开头用户消息中的"强制语言规则"段落
就是该 hook 的注入产物——它不是手打的。

### 4. Agent 可见文本输出 → 中文效果验证

规则/hook 只是**倾向性指令**，模型仍可能漂移。验证手段：

- 人工观察：新开会话给任务，看可见思考说明是否为中文；
- `tests/check_drift.py`：把界面复制出的可见文本保存为 .txt，
  离线统计中英文段落分布（剔除代码、日志、路径、标识符）；
- `docs/manual-test-matrix.md`：10 个场景的人工测试矩阵。

## 三、必须澄清的边界

> **"规则请求中文输出" ≠ "已证明隐藏内部推理是中文"。**

- 模型的**不可见内部推理**（hidden reasoning）不在规则、hook、
  翻译器的任何可控范围内，本项目不对其做承诺，也无法观测。
- 本项目约束的是模型**显式生成、展示给用户的文本**：
  Thoughts 栏的思考说明、计划、工具调用前的说明、回复与总结。
- 可见文本是模型直接用中文生成的（非事后翻译），这是经验观察，
  未经严格基准验证；推理质量是否受影响同样没有对照实验支撑。

## 四、可见文本经 Ollama 翻译的独立流程

```
用户在 Devin 界面看到英文可见文本
   │  用户手动复制（唯一合法来源）
   ▼
保存为 .txt → scripts/translate_ollama.py
   │  仅允许 127.0.0.1/localhost endpoint
   ▼
本机 Ollama（如 qwen2.5:7b）逐段翻译
   │  代码块/行内代码/路径/URL/JSON/SQL/含中文行 → 原样保留
   │  sha256 缓存去重 + 失败重试
   ▼
输出 .zh.md：中文译文 + 英文原文引用对照
```

要点：

- 这是**事后对照翻译**，不改变模型输出本身，更不是"模型用中文推理"；
- `--mock` 模式输出 `[模拟译文]` 前缀，仅用于演示；
- **原生实时集成未实现**：Devin 未公开获取已展示文本的接口，
  不做 DOM/CDP 抓取、流量解密、令牌窃取或客户端注入；
- Ollama 不是规则模式的依赖，完全可选。
