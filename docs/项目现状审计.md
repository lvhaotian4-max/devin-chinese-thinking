## 二、本机实际生效的三层机制（实测）

### 层 1：全局规则文件（always-on，随会话启动注入）

| 文件 | 本机状态 | 内容 |
|---|---|---|
| `%APPDATA%\devin\AGENTS.md` | ✅ 存在，被加载 | v1 风格语言规则（简体中文回复 + thinking/reasoning 全程中文 + 标识符保留原文） |
| `%USERPROFILE%\.codeium\windsurf\memories\global_rules.md` | ✅ 存在，被加载 | 与上面几乎相同的语言规则 |

证据：本会话系统提示中同时出现这两个文件的 `<rules>` 块，内容与磁盘文件一致。

### 层 2：生命周期 Hooks（每次提示重新注入，关键机制）

`%APPDATA%\devin\config.json` 中注册了 hooks：

```json
"hooks": {
  "SessionStart":     [{ "matcher": "", "hooks": [{ "type": "command",
    "command": "node \"C:/Users/20773/AppData/Roaming/devin/hooks/chinese-thinking.mjs\" SessionStart", "timeout": 5 }] }],
  "UserPromptSubmit": [{ "matcher": "", "hooks": [{ "type": "command",
    "command": "node \".../chinese-thinking.mjs\" UserPromptSubmit", "timeout": 5 }] }]
}
```

`hooks/chinese-thinking.mjs` 在每次用户提交 prompt 时向 stdout 输出
`hookSpecificOutput.additionalContext`，内容为强制简体中文推理/输出的指令。

**这就是本会话开头那条"强制语言规则"用户消息的来源**——它不是用户手打的，
而是 hook 注入的 additionalContext。官方文档
`extensibility/hooks/lifecycle-hooks.mdx` 确认 `UserPromptSubmit` 和
`SessionStart` 均为受支持事件，`additionalContext` 为官方输出字段。

意义：规则文件只在会话启动时注入一次，长上下文中可能被稀释；
**hook 在每个 prompt 都重新注入**，是抗漂移的最强手段。
仓库现有 install.ps1 **完全不涉及 hooks**——这是审计发现的最大缺口。

### 层 3：IDE 界面语言包（与思考链无关，仅供完整记录）

`%APPDATA%\devin\languagepacks.json` + `devin-zh.json`：VS Code 中文界面语言包
（`ms-ceintl.vscode-language-pack-zh-hans`），只汉化 IDE 菜单/界面文字，
**不影响 Agent 输出语言**。仓库未涉及，本文档仅记录以免混淆。

## 五、诚实边界声明

- "规则请求中文输出" ≠ "已证明隐藏内部推理为中文"。本项目约束的是
  **模型显式生成的可见文本**（思考说明、计划、工具说明、回复、总结）。
- hooks 注入的也是**可见上下文指令**，同样不触及不可见推理。
- 本机三层机制同时存在，无法精确归因中文效果来自哪一层；
  但 hooks 每 prompt 重注入在机制上最能解释"长会话不漂移"。
- `~/.devin/rules` 路径有官方文档依据，但在 Devin Desktop 1.141.2
  上的实际加载**未经本机验证**（该文件本机不存在）。
